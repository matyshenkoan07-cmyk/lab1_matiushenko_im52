# Специфікація (spec.md) — Завдання 5: Архітектура та компонентна модель

## 1. Намір та мета
Побудувати UML Component Diagram (у декларативному синтаксисі Mermaid) для платформи онлайн-репетиторства, що об'єднує всі попередні моделі (дані з Лабораторної 1, сценарії `UC-1..UC-4` з Лабораторної 2, взаємодію з Лабораторної 3 та процес бронювання/оплати з Лабараторної 4) у єдину архітектуру з чіткими межами системи, компонентами та інтерфейсами.

## 2. Межі системи та склад компонентів

### Внутрішні компоненти системи (System Boundary: TutorPlatform)
1. **Рівень представлення (UI):**
   - `WebClient` (клієнтський веб-інтерфейс для учнів і репетиторів).
2. **Рівень входу (API Gateway / Backend Entry):**
   - `APIGateway` (маршрутизація HTTP-запитів, перевірка токенів авторизації).
3. **Сервісний рівень (Бізнес-логіка):**
   - `AuthService` (реєстрація, аутентифікація, керування профілями `Student` і `Tutor`).
   - `CatalogService` (пошук репетиторів, фільтрація за предметами `Subject` та розкладом).
   - `BookingService` (керування слотами та життєвим циклом заняття `Lesson`: `Available` → `Pending_Payment` → `Confirmed` / `Cancelled`).
   - `PaymentService` (ініціація платіжних сесій, обробка вхідних webhook-сповіщень та контроль 15-хвилинного тайм-ауту).
   - `NotificationService` (формування та відправка Push/Email сповіщень про статус бронювання).
4. **Рівень доступу до даних та сховище:**
   - `DataAccessLayer` (репозиторії для роботи з сутностями `Student`, `Tutor`, `Subject`, `Lesson`).
   - `Database` (реляційна СУБД PostgreSQL).

### Зовнішні інтеграції (поза межами системи)
- `PaymentGateway` (зовнішня платіжна система, напр. LiqPay / Stripe — приймає запити на оплату та надсилає webhook).
- `NotificationProvider` (зовнішній шлюз доставки Email/Push-повідомлень).
- `OAuthProvider` (зовнішній провайдер ідентифікації, напр. Google OAuth).

## 3. Критерії прийняття (Acceptance Criteria)
- **AC-1 (Межа системи):** Усі внутрішні модулі чітко згруповані всередині контейнера `TutorPlatform`, а `PaymentGateway`, `NotificationProvider` та `OAuthProvider` винесені за межі системи.
- **AC-2 (Інтерфейси `provided` / `required`):** Для ключових взаємодій явно позначені інтерфейси (напр., `IBookingAPI`, `IPaymentAPI`, `IPaymentWebhook`, `INotificationSender`, `IDataRepository`).
- **AC-3 (Шарування залежностей):** `WebClient` звертається виключно до `APIGateway`; бізнес-сервіси взаємодіють з `Database` лише через `DataAccessLayer` (жодних прямих зв'язків UI → БД або сервіс → БД).
- **AC-4 (Трасування до Лаб 1–4):** Компоненти покривають усі сутності моделі даних (`Student`, `Tutor`, `Subject`, `Lesson`) та сценарій бронювання й оплати (`UC-2` + `UC-4`).
- **AC-5 (Поза обсягом / Out of Scope):** Мікросервісний брокер повідомлень (Kafka/RabbitMQ), CDN для медіафайлів та кешування Redis свідомо виключені для поточної ітерації.
