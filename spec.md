# Специфікація моделі даних (spec.md)
## 1. Сутності та атрибути
### User (Користувач)
Позначає зареєстрованого користувача платформи, який може бути учнем або репетитором.
* `id` — унікальний ідентифікатор користувача (Primary Key).
* `full_name` — повне ім'я та прізвище.
* `email` — електронна пошта (унікальна).
* `role` — роль у системі (`student` або `tutor`).
* `created_at` — дата та час реєстрації.
### TutorProfile (Профіль репетитора)
Надає додаткові дані про викладача і умови його навчання.
* `id` — унікальний ідентифікатор профілю (Primary Key).
* `tutor_id` — ID користувача-репетитора (Foreign Key -> `User.id`).
* `experience` — досвід викладання (кількість років або місяців).
* `price_per_hour` — базова вартість за годину заняття.
* `biography` — дані про освіту, методику і досягнення.
### Subject (Предмет)
Дисципліна, з якої проводяться заняття.
* `id` — унікальний ідентифікатор предмета (Primary Key).
* `name` — назва предмета (наприклад, Математика, Англійська мова, Фізика).
* `description` — короткий опис напряму або програми.
### Lesson (Заняття)
Описує факт бронювання заняття між учнем і репетитором певного предмета.
* `id` — унікальний ідентифікатор заняття (Primary Key).
* `student_id` — ID учня, який забронював урок (Foreign Key -> `User.id`).
* `tutor_id` — ID репетитора (Foreign Key -> `User.id`).
* `subject_id` — ID предмета (Foreign Key -> `Subject.id`).
* `start_time` — дата та час початку заняття.
* `duration_minutes` — тривалість у хвилинах (наприклад, 60 або 90).
* `status` — статус заняття (`scheduled`, `completed`, `cancelled`).
* `price` — вартість конкретного заняття.
## 2. Критерії прийняття (Acceptance Criteria)
* Модель даних повинна бути нормалізована (3NF).
* Усі зв'язки між сутностями мають бути явними та безпомилковими (без прямих зв'язків Many-to-Many).
* Кожна сутність повинна мати Primary Key (`id`).
* Зовнішні ключі (Foreign Keys) мають чітко посилатися на відповідні первинні ключі батьківських сутностей.
